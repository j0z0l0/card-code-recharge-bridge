# 四种接入模式

## A. 没有支付，也没有兑换

建立最小连接层：

- 应用商品读取；
- 本地待支付订单；
- 卡密平台下单适配；
- 服务端查单；
- 获取卡密；
- 最小兑换/权益发放；
- 幂等、限流、异常队列；
- 管理端状态查看。

只建立打通链路所需能力，不扩展成完整商城。

## B. 有兑换，没有在线支付

优先复用现有兑换逻辑：

- 新增本地支付订单；
- 应用商品映射到平台商品；
- 拉起收银台；
- 查单并取码；
- 调用现有兑换函数；
- 订单成功后返回应用权益。

关键要求：自动兑换与手动兑换必须共用同一个兑换实现。

## C. 有支付，没有兑换或权益发放

保留现有支付订单：

- 增加平台订单映射；
- 增加卡密库存或兑换表；
- 增加兑换校验和权益发放；
- 绑定已有支付成功状态；
- 增加幂等和对账。

不要另建一套支付状态机。

## D. 支付和兑换都有

先审计，不重写：

- 订单归属和金额校验；
- 支付成功与权益发放的边界；
- 卡密消费和重复兑换；
- 并发轮询；
- 查询接口限流；
- 重复付款；
- 平台金额；
- 卡密库存；
- 人工兜底。

只修改打通链路所需的最小部分。

## 商品映射

- 从应用读取现有商品 ID、价格、发放权益；
- 从平台商品链接或适配器读取商品 ID、价格和名称；
- 先按商品 ID，再按价格和名称生成候选映射；
- 不确定时只向用户确认具体对应关系；
- 不在 Skill 中新增或修改商品档位。
